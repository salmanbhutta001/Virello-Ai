# Vercel (serverless) requirements — slimmed for the 500 MB function bundle.
# Vercel installs THIS file by default; do NOT set a custom installCommand
# (a custom install command disables Vercel's Python bundle handling and
# drops the effective limit to 225 MB — deploy dpl_GdfM failed on that).
#
# Dropped vs requirements-full.txt (Railway/Docker/local keep the full set):
#   - rembg + onnxruntime (+ scipy, numpy, numba, llvmlite, scikit-image,
#     networkx, imageio, tifffile, pooch, pymatting): background removal.
#     Imported lazily in app/services/bg_remover.py; the admin
#     remove-backgrounds endpoint degrades on Vercel.
#   - pytrends (+ pandas, lxml): Google Trends connector already guards
#     the import (app/services/audience_sources/google_trends.py,
#     try/except -> _PYTRENDS=False); audience sources fall back.
#   - google-auth + google-api-python-client (~120 MB of discovery docs):
#     Play Billing client is built lazily in
#     app/services/payments/google_play.py and 503s without a service
#     account anyway (VIRELLO_PLAY_SERVICE_ACCOUNT_JSON is unset).
#   - uvicorn[standard]: local dev server only; Vercel serves ASGI itself.
#     (uvloop, watchfiles, websockets, python-dotenv go with it.)
#   - psycopg[binary]: MUST STAY (fixed deploy 3, 2026-10-28). The Neon
#     DATABASE_URL is a plain postgresql:// string, and SQLAlchemy 2.1
#     resolves that scheme to the ASYNC psycopg dialect at engine creation
#     (app/core/database.py import). Without the package the import raises
#     ModuleNotFoundError 'psycopg' and the whole API 500s on every route
#     (FUNCTION_INVOCATION_FAILED) — local sqlite import tests never catch
#     this because sqlite never loads the postgres dialect. ~19 MB.
#   - alembic: migrations never run on Vercel (init_db() bootstraps).
#

# site-packages; this file installs ~175 MB. Verified: app.main imports
# cleanly with this set incl. a plain postgresql:// DATABASE_URL (48 routes).
